This walkthrough builds a guestbook app from scratch — generating specs, building the plugin and frontend, and running everything locally. It follows the workflow described in the main article.

1. Generate the Spec

Start Claude Code in the canopy-llm directory and run the spec generator:

> /generate-spec

Claude reads the spec templates, then asks what the app does and follows up with a few targeted questions to fill in the details.

Figure 1. Claude working through /generate-spec for a Polymarket-style app — asking about app name, deadline type, refund behavior, and visual style

Claude will ask a series of questions. Here’s the full interaction:

1.1. Choosing the App

Claude: What kind of app would you like to build?

You: A public guestbook. Anyone with a wallet can post a short message on-chain. Messages are immutable — no editing or deleting.

1.2. Plugin or Frontend?

Claude: Do you need a plugin spec, a frontend spec, or both?

You: Both

1.3. Naming

Claude: What should the app be called? This determines the spec filenames and directory names.

You: guestbook

Claude creates specs/guestbook-plugin.md and specs/guestbook-frontend.md.

1.4. Plugin Details

Claude walks through each section of the plugin spec:

Claude: What transaction types does the guestbook need?

You: Just one: post_message. Fields: sender_address (bytes), message (string, max 280 chars).

Claude: What state objects should be stored on-chain?

You: A Message with id, author_address, content, and block height. A MessageCounter with next_id for auto-incrementing IDs.

Claude: Any business logic details for post_message?

You: Validate sender_address is 20 bytes, message is non-empty and ⇐ 280 chars. Increment the counter, store the message with the current block height.

Claude: What should the WebSocket broadcast?

You: EndBlock broadcasts the last 50 messages ordered by id descending as { "type": "end_block", "height": 123, "messages": […​] }

1.5. Frontend Details

Claude: What visual style should the frontend use?

You: Dark terminal aesthetic — near-black background (#0D1117), bright green accent (#00FF88), monospace font for messages.

Claude: What are the key UI features?

You: Wallet connect top-right. A textarea for posting messages with a live 280-char counter. A scrolling feed of messages, newest first, with author address and block height. New messages animate in via WebSocket.

Claude: Any constraints?

You: Messages are immutable. WebSocket updates should use useReducer with a Map to avoid full re-renders.

Claude writes both specs to specs/. You can review and edit them before building.

2. Build the App

Run the build command:

> /build-app guestbook
Figure 2. Claude runs a protocol agent first to establish message contracts, then launches the plugin and frontend agents in parallel

Claude runs three phases:

  1. Protocol agent — reads both specs and the canopy-crypto SDK, then writes specs/guestbook-PROTOCOL.md with WebSocket message shapes, transaction wire formats, address encoding rules, and Vite proxy config.

  2. Plugin agent — copies the plugin template from $CANOPY_SRC, defines proto messages, runs protoc, implements CheckTx/DeliverTx handlers, wires up WebSocket broadcasts in EndBlock, and verifies with go build ./…​.

  3. Frontend agent — scaffolds a Vite + React 18 + TypeScript project, registers message types with canopy-crypto, implements the wallet flow, message feed, and post form, then verifies with npm install && npx vite build.

The plugin and frontend agents run in parallel. When both complete, Claude reports the results:

Plugin (guestbook-plugin/plugin/go):
- 1 transaction type: post_message
- State prefixes: {24} messages, {25} counter
- go build ./... passes clean

Frontend (guestbook-frontend/):
- Vite + React 18 + TypeScript
- Dark terminal aesthetic
- vite build passes clean (0 errors)

3. Start the Plugin

Build the plugin binary and start Canopy:

cd guestbook-plugin/plugin/go
make build      # Compiles to ./go-plugin
cd ../..        # Back to guestbook-plugin/
canopy start    # Launches plugin automatically via pluginctl.sh

Verify the plugin connected by checking the logs:

tail -f /tmp/plugin/go-plugin.log

You should see:

WebSocket server starting on :36660/ws
Handshaking with FSM

4. Start the Frontend

In a separate terminal:

cd guestbook-frontend
npm install
npm run dev

Vite starts on http://localhost:5173. Open it in a browser.

5. Test the App

5.1. Connect a Wallet

  1. Click Connect Wallet in the top-right

  2. Select an account from the keystore list

  3. Enter the password to unlock

5.2. Post a Message

  1. Type a message in the textarea (up to 280 characters)

  2. Click Post

  3. The transaction is submitted to the chain

  4. On the next block, the message appears in the feed via WebSocket

5.3. Verify On-Chain

You can query the account balance directly to confirm the transaction fee was deducted:

curl -X POST http://localhost:50002/v1/query/account \
  -H "Content-Type: application/json" \
  -d '{"address": "<your-address-hex>"}'

6. Project Structure

After generation, the directory layout is:

canopy-llm/
├── specs/
│   ├── guestbook-plugin.md        # Plugin spec
│   ├── guestbook-frontend.md      # Frontend spec
│   └── guestbook-PROTOCOL.md      # Protocol bridge document
├── guestbook-plugin/
│   └── plugin/
│       └── go/
│           ├── contract/
│           │   ├── contract.go     # CheckTx, DeliverTx, EndBlock
│           │   ├── market.go       # Handler implementations
│           │   ├── error.go        # Error definitions
│           │   └── plugin.go       # Socket comms, WS dedup
│           ├── proto/
│           │   └── tx.proto        # Message definitions
│           ├── go.mod
│           ├── main.go
│           ├── Makefile
│           └── pluginctl.sh
└── guestbook-frontend/
    ├── src/
    │   ├── App.tsx
    │   ├── sdk.ts                  # Message type registration
    │   ├── types.ts
    │   ├── useMarkets.ts           # WebSocket hook
    │   └── useWallet.ts            # Wallet connection
    ├── package.json
    ├── vite.config.ts
    └── index.html

7. Iterating

If something isn’t right after generation, you can ask Claude to make changes directly:

> increase the max message length to 500 characters
> add a delete_message transaction that only the author can call
> change the font to Inter and make the background lighter

Claude will edit the generated code in place. For structural changes like adding a new transaction type, it updates the proto, regenerates, and modifies the handlers.

To start fresh, delete the generated directories and run /build-app guestbook again.
